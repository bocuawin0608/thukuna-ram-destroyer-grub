## 1. Supported Linux Distributions & Package Managers

[`scripts/detect-system.sh`](../scripts/detect-system.sh) and [`scripts/detect-bootloaders.sh`](../scripts/detect-bootloaders.sh) dynamically inspect `/etc/os-release`, available package managers, and GRUB binary/configuration paths rather than assuming a fixed filesystem layout.

| Distribution Family | Package Manager | Config Generator | Active Config Path(s) | Verification Level |
| :--- | :--- | :--- | :--- | :--- |

## 2. Universal Operating-System Detection Policy

INFERNAL **never hardcodes operating-system entries** into the theme or overwrites `/boot/grub/grub.cfg` with a static template. Instead:
1. GRUB dynamically populates `+ boot_menu` from the active `grub.cfg` generated by `grub-mkconfig` / `grub2-mkconfig`.
2. Each entry's `--class <distro>` attribute is mapped automatically by GRUB to [`theme/icons/<class>.png`](../theme/icons/) (`endeavouros`, `arch`, `manjaro`, `windows`, `ubuntu`, `debian`, `fedora`, `opensuse`, `linuxmint`, `nixos`, `gentoo`, `void`, `recovery`, `uefi`, `memtest`, `gnu-linux`, `linux`).
3. Existing `/etc/grub.d/40_custom` entries, `/boot/grub/custom.cfg` entries, recovery submenus, and `UEFI Firmware Settings` (`fwsetup`) entries are preserved untouched.

### Capability Boundaries & Known Limitations

- **Multi-boot OS Discovery (`os-prober`)**: GRUB 2.06+ disables `os-prober` by default unless `GRUB_DISABLE_OS_PROBER=false` is set in `/etc/default/grub`. INFERNAL inspects and reports the current `GRUB_DISABLE_OS_PROBER` policy during `--check` and `--dry-run`, and **preserves** your existing setting without silently enabling `os-prober` globally.
- **Encrypted Root / LVM / Btrfs Subvolumes**: Other Linux installations residing on locked LUKS containers or unmounted Btrfs subvolumes without an accessible `/boot` partition cannot be discovered by `os-prober` unless unlocked/mounted or chainloaded via their own EFI stub in `/etc/grub.d/40_custom`.
- **Alternative Boot Managers (`systemd-boot`, `rEFInd`)**: If the system uses `systemd-boot` (`/boot/loader/loader.conf`) or `rEFInd` without an active GRUB configuration, `./install.sh` detects this and aborts safely. INFERNAL themes GNU GRUB only and never alters NVRAM boot order or replaces another boot manager.
- **Secure Boot**: When UEFI Secure Boot is enabled, some distributions restrict loading unsigned external `.pf2` fonts from outside the signed EFI binary or require fonts on a trusted partition. `scripts/detect-bootloaders.sh` reports the active Secure Boot state so administrators are aware before installing.
- **GRUB Animations / Video**: Standard GRUB `gfxmenu` does not support MP4/WebM video playback or CSS/shader animations. INFERNAL uses static high-contrast 9-slice PNG pixmaps and pre-rendered `.pf2` bitmap fonts for immediate, zero-lag boot rendering.

## 3. Verification Classification

To maintain strict engineering transparency, test coverage is categorized as follows:

1. **Automated Unit Tests (`tests/test-detection.sh`)**:
   - 24 assertions testing `/etc/os-release` parsing, package manager resolution (`pacman`, `apt-get`, `dnf`, `zypper`), UEFI vs. Legacy BIOS detection, `systemd-boot` rejection, missing `grub-mkconfig`, missing optional dependencies, and GRUB Legacy `0.97` rejection.
2. **Isolated Integration Tests (`tests/test-installer.sh`, `tests/test-idempotency.sh`)**:
   - 29 assertions executing full `--dry-run`, `--install`, interrupted install + automatic rollback, read-only filesystem error handling, 12-entry long-OS-name menus validated by the host's real `/usr/bin/grub-script-check`, 3-run idempotency verification, and byte-for-byte baseline restoration via `./uninstall.sh`.
3. **Real Hardware / Host Verification**:
   - Executed `./install.sh --check`, `./install.sh --dry-run`, and `./scripts/validate-theme.sh` against the live **EndeavourOS (`x86_64`, UEFI, `GRUB 2:2.16-1`)** host without modifying the host's active `/boot` or `/etc/default/grub`.
4. **Untested Claims**:
   - Physical reboot across every third-party distribution (`Fedora`, `openSUSE`, `Debian`) was validated via isolated filesystem sandboxes and `grub-script-check`, not physical bare-metal reboots on those distributions.
